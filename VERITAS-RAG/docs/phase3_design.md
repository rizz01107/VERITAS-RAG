# Phase 3 design: document ingestion

Status: implemented and tested on **synthetic PDFs only**. No real paper has been parsed, nothing was benchmarked, all experiment fields remain NOT RUN / PENDING EXPERIMENT.

## Pipeline (`app/ingestion/`)
`validation.py` (type, size, `%PDF-` header, read once into memory, SHA-256) -> `pymupdf_backend.py` (backend-neutral `RawPage/RawBlock/RawLine/RawSpan`) -> `layout.py` (style-change split, overprint dedupe, running-header/page-number removal, reading order incl. two columns) -> `sections.py` (title block, headings, references/appendix state) -> `cleaning.py` (conservative text cleaning, vocabulary-checked de-hyphenation) -> `metadata.py` (title/authors with recorded source) -> `pipeline.py` (offsets, `ParsedDocument`) -> `io.py` (deterministic JSON, atomic, collision-safe names).

Every `TextUnit` carries: `document_id`, `page_number` (physical, 1-based), `section`, `section_level`, `is_reference`, `bbox`, `column`, `extraction_method`, `char_start/char_end` into `ParsedDocument.full_text` (validated on construction and on reload), and the document carries `source_file` (portable POSIX-style, never absolute) and `source_url`. `ParsedDocument.chunk_units()` is the chunk-ready view (references excluded by default).

Failures never raise at the document level: `IngestionResult(status=failed, failure=IngestionFailure(code, message, stage, ...))` with codes `file_not_found, not_a_file, unsupported_type, empty_file, file_too_large, not_a_pdf, corrupted, encrypted, empty_document, too_many_pages, no_text_layer, ocr_not_implemented, parse_error, unsafe_path`. Partial results (some pages without text, repaired PDF, U+FFFD found) get `status=partial` plus per-page warnings. Foreign-library exceptions are converted at the backend boundary only; bugs in our own code still raise.

## OCR decision
OCR is **not implemented** and Tesseract is **not introduced**. Detection comes first: pages with fewer than `min_chars_per_page` characters are flagged (`no_text_layer_page` when images exist). An image-only document fails with `no_text_layer`; with `ocr_enabled: true` it fails with `ocr_not_implemented` (explicit, "IMPLEMENTATION PENDING"), never silently. If OCR is ever added, units must carry `extraction_method=ocr`; the field and schema already exist. Whether OCR is needed for your corpus is unknown until your real PDFs are ingested (born-digital arXiv PDFs normally have a text layer).

## Windows notes
Developed on Linux; **the full pytest suite was run on Windows 10.0.26200 / Python 3.10.0 / PyMuPDF 1.28.2 by the project owner (236 passed, 15 skipped: 14 need pdflatex, 1 symlink; see `docs/phase3_validation.md`)**. What is designed/tested for it: pathlib throughout; UTF-8 explicit for all text I/O; ASCII-safe JSON on stdout; file read fully into memory so no handle stays open (a test deletes the file right after ingestion); Windows reserved names, illegal characters, trailing dots/spaces handled and unit-tested via pure functions; `PureWindowsPath` tests for provenance names (no `C:\Users\...` leaks); atomic writes with `os.replace` (can fail on Windows if another process holds the target open); symlink tests skip when symlinks are not permitted. Verified on that machine: the PyMuPDF wheel and the suite. Not verified: long-path limits, real corpus PDFs, and the TeX ground-truth tests (no `pdflatex` on that machine). No `make`: use `python -m pytest`, `ruff check .`, `ruff format --check .`, `mypy`; set `$env:PYTHONHASHSEED=0` in PowerShell.

## Known limitations (also the second-review findings that remain open)
* Two-column ordering is heuristic (>= 2 blocks per half + vertical overlap; spanning blocks separate segments). Three or more columns, sidebars and footnote blocks are not handled. A paragraph continuing across a column or page break remains two units (no cross-block merging; hyphenation is repaired only within a block).
* Heading detection uses font size/boldness and numbering; unnumbered, same-size headings and unusual styles are missed (section stays at the previous heading). Letter-numbered headings can be false positives. A References list without a heading is flagged (`no_references_section`) but not separated.
* Table detection relies on PyMuPDF `find_tables`; unruled tables and ruled figures are error-prone; it is skipped on pages above `table_detection_max_lines` (warning) because it is superlinear.
* Rotated pages are extracted but flagged `rotated_page` (coordinates and order unverified). Right-to-left scripts, superscript/footnote markers fused into words, and text rendered as images are not handled.
* De-hyphenation is a vocabulary heuristic: a compound that only ever appears broken across lines may lose its hyphen.
* Layout text order, section assignment and reference separation have **not been validated on real papers**. Use the manual protocol below.
* Security: PyMuPDF is a native library; size/page limits exist, but decompression bombs and parser crashes are not sandboxed. Untrusted uploads (Phase 16) must parse in a subprocess with timeouts and memory limits. PDF scripts/embedded files are never executed or extracted. Document text is evidence, never instructions (an adversarial-text test verifies it is kept verbatim as data).

## Manual validation protocol for real PDFs (results: NOT RUN)
After you download papers: `python -m app.cli ingest --paper-id <id>`; per document check `pages`, `text_layer_pages`, `warnings`, and the `headings` list against the PDF; spot-check 5 random units per document (page number, text, order) and all tables; record outcomes in a sheet (`reports/ingestion_validation.csv`: paper_id, page, unit_id, check, pass/fail, note). Do not proceed to chunking experiments until failures are understood.

## Verification evidence (Phase 3)
**Phase 3 snapshot (current results: `PROJECT_STATUS.md`).** Python 3.12.3 / Linux: 214 tests passed at that time; `ruff check`, `ruff format --check`, `mypy --strict` clean (64 files); a fresh venv built only from `requirements/dev.txt` reproduces the identical package set and passes; the suite also passes with PyMuPDF 1.26.7 and pydantic 2.7.4. 24 deliberate defects (page-number shift, offset drift, column order, reference flagging, header removal, ligatures, de-hyphenation both ways, encrypted/size/header checks, reserved names, path traversal, text-layer detection, overprint dedupe, table duplication, path leak, status downgrade, download guards, junk title, licence/access rules) were each caught by the tests. Ingestion is byte-deterministic (same file -> identical JSON).

## Second-review defects found and fixed
Heading units used uncleaned text (ligatures/soft hyphens leaked into section names) -> cleaned; a 14 pt title was classified as a section heading -> title-block detection (leading blocks, not numbered/known/appendix headings); damaged pages or unexpected parser exceptions could escape as raw exceptions -> per-page `page_load_failed` warning and `parse_error` failure; sanitised output filenames could collide (`paper.` vs `paper`) -> hash suffix; paper ids differing only by case would collide on Windows -> case-insensitive uniqueness in the manifest; rotated pages unflagged -> warning; PyMuPDF wrote advisories to stdout (corrupting CLI JSON) -> suppressed; `find_tables` took ~30 s on a 600-line page -> cap + linear dedupe; two de-hyphenation vocabulary flaws -> fragment-free vocabulary and "keep a hyphen if the hyphenated form exists".
